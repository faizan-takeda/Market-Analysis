# MEDICINE 2040 — Executive Intelligence Application

React 18 + TypeScript + Vite 5 + D3 7. Reads only `public/data/*.json`, generated by `../scripts/build_app_data.py` from the evidence registries and curated markdown. The app stores no research: `src/narrative.ts` holds claim IDs and framing prose only, and tests fail on research numbers, years or claim IDs as literals in UI code.

## Run
From the MEDICINE root: `./launch.sh` (validate → data → build → test → serve on http://127.0.0.1:4173/).
Dev: `cd executive_application && npm run data && npm run dev`. Tests: `npm test` (data integrity, then server-side render of every route, including a test-only strategy fixture).

## Views (hash routes)
1 `/` Future of Medicine · 2 `/powerhouses` · 3 `/differentiators` · 4 `/pipeline` · 5 `/observatory` · 6 `/ecosystem` · 7 `/encyclopedia` · 8 `/takeda` · 9 `/strategy` · 10 `/portfolio` · 11 `/roadmap` · 12 `/uncertainty` · `/research-graph`.
Any claim or source ID opens the keyboard-accessible Evidence drawer (Esc closes). Missing datasets render an explicit notice; strategy views show "Strategy module not yet produced — see PROJECT_STATE.md".

## Datasets (`public/data/`, written by the pipeline)
claims, sources, financials, products, knowledge_graph, research_graph, coverage, maturity, maturity_matrix, project_state, search_index, timelines (company timeline.md), mechanism_cards (cards and moats.md), deals (edges jsonl and deal_inventory.md), approvals and setbacks (pipeline_regulatory; `available:false` until the files exist), takeda_baseline (capability classes and IVB backlog), conflicts, strategy (all contract files, `available` per file).
Every claim ID in every dataset is validated against the registry; an unknown ID fails the pipeline (exit 1). SQLite mirror: `data/database/medicine.sqlite`.

## Strategy contract
`../strategy/DATA_CONTRACT.md`. Files in `../strategy/data/` are validated (claim IDs, `ASM-` and `BET-` references) and passed through in `strategy.json`.


## Wave 5 (final pass)
- Navigation: `.pillars` wraps instead of scrolling; all eleven pillars show at 1280 and 1440 px in one row, two rows at 1024 px.
- Future Plan hub (`FutureHub` in `src/pages.tsx`): ordered module flow (domains, bets, capital, scenarios, roadmap, council, counterarguments) with report word counts, record counts and reader links.
- Council page renders a bet x council verdict matrix when `council_reviews.json` exists; View 12 renders counterarguments when `counterarguments.json` exists. Absent files keep an explicit notice.
- `deliverables/*.md` are bundled (section `deliverables`) and listed first in the Overview reading guide.
- Ask: per-part prompt (`src/llm.ts`), sub-question fallback (`retrievePartial` in `src/qa.ts`), citation audit also accepts claim IDs present in the passage text. `node tests/llm_probe.mjs "<q>"` exercises it against a local Ollama.
- Build order: `python3 ../scripts/build_app_data.py` -> `npm run build` -> `python3 ../scripts/build_single_file.py` -> `npm test`.

## Hub additions
- **Pillar navigation** (`src/pillars.ts`): Overview, Companies, Commercial, R&D/Pipeline, Data·AI·Robotics, Partnerships, Policy, Takeda Baseline, Future Plan (forward-looking banner), Evidence & Method, Ask. Pages in `src/pages.tsx`; views 1-12 unchanged under their pillars.
